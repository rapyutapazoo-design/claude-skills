# 計画書作成スキル (Plan Creator)

コンサルタントモードで検討・採用された案を受け取り、実装計画書をテキストで生成するスキル。
プロジェクトのコード・ファイルは変更しない。計画書は auto-flow への引き継ぎ用に `~/.claude/handoff/` にも保存する。

---

## 起動後の動作フロー

### ステップ 1: 採用案の特定

会話履歴を参照し、直近のコンサルタントモードで「推奨案」または「採用案」として決定された内容を抽出する。
会話履歴に無い場合（別セッションで検討した場合）は、`~/.claude/handoff/<repo-key>/` の `kind: design`・`status: adopted` のうち話題が一致する最新のファイルを読み取って採用案とする（形式と repo-key は `~/.claude/skills/consultant-mode/references/handoff_format.md`）。

**抽出できた場合** → そのままステップ 2 へ進む。

**抽出できなかった・曖昧な場合** → ユーザーに確認する:
> 「採用する案を教えていただけますか？（例: アプローチ B、ハイブリッド案など）」

---

### ステップ 2: 計画書の生成

抽出した採用案をもとに、以下のフォーマットで計画書を出力する。

### ステップ 3: 計画書の保存（auto-flow への引き継ぎ）

出力した計画書の全文を、`~/.claude/skills/consultant-mode/references/handoff_format.md` の形式で `~/.claude/handoff/<repo-key>/` に新規保存する。

- `kind: plan`、`source: plan-creator`。`adoption_quote` には採用を決めたユーザー発話の原文（無ければ計画書作成を依頼した発話）を入れる
- 採用案を handoff ファイルから読んだ場合は、そのファイル名を `design_ref` に入れる（元ファイルは変更しない）
- `repo` / `base_sha` は読み取り専用の `git rev-parse --show-toplevel` / `git rev-parse HEAD` で取る（repo 外なら null）
- 保存後に1行表示する: `📥 計画書を保存しました: ~/.claude/handoff/<repo-key>/<ファイル名>`
- 秘密情報を含む話題では保存せず、その旨を1行伝える

---

## 計画書フォーマット

```
# 実装計画書: [テーマ]

## 採用案サマリー
- **採用案:** [案の名前・概要]
- **採用理由:** [検討時に挙げられた理由]

## 実装ステップ
1. [作業内容] — [対象ファイル・モジュール・備考]
2. ...（番号付きで順序通りに記載）

## 考慮事項
- **リスク:** [潜在的な問題点]
- **依存関係:** [前提となる作業・ツール・設定]
- **注意点:** [実装時に気をつけるべき点]

## 完了条件
- [ ] [計画が完了したと判断できる具体的な基準]
- [ ] ...
```

---

## 禁止事項

- プロジェクトのファイルの書き込み・編集（Write, Edit ツールの呼び出し。例外はステップ 3 の `~/.claude/handoff/` への新規作成のみ）
- コマンドの実行（Bash でのシステム変更。読み取り専用の `git rev-parse` は可）
- 実装可能な状態のコードブロックの生成

計画書はあくまでテキスト出力のみ。実装作業は「実装してください」とユーザーが発言してから別途行う。

---

## 次のスキルへの誘導

計画書出力後、末尾に以下を案内する:

> 「この計画書でよければ「**実装してください**」とお伝えいただくと実装に着手します。別セッションで auto-flow を起動した場合も、保存した計画書が引き継がれます。」
